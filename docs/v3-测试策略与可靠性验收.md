# FileSync v3.0：测试策略与可靠性验收

> 状态：实现与发布门禁（Release Gate）
> 原则：同步软件的正确性不能只靠正常路径演示；必须验证故障、重启、并发和数据一致性。

## 1. 测试分层

### 1.1 单元测试

覆盖：
- 三方判定表的所有存在/修改/删除组合；
- 完整指纹相同、不同、缺失、计算失败；
- 删除/修改冲突、首轮双端已有内容；
- 路径比较、大小写碰撞、Unicode、非法名称；
- 删除熔断、排除规则、重命名候选歧义；
- Journal 编码、CRC、部分写入、序号连续性、Snapshot 切换；
- Operation 状态转换和恢复决策。

### 1.2 属性测试 / 随机模型测试

建立一个纯内存参考模型，随机生成 A/B 文件操作序列：
- 创建、修改、删除、重命名；
- 同一文件两侧并发修改；
- 操作后同步、同步中断、重启；
- 随机网络/权限/磁盘错误。

性质要求：
1. 无冲突时最终两端内容收敛；
2. 有冲突时双方版本至少有一份可恢复副本；
3. 未完成/不完整扫描不能传播删除；
4. 重复执行同一 Operation 不产生重复破坏；
5. 任意崩溃点恢复后 Base 与实际文件状态一致或明确进入人工恢复态；
6. 随机操作后不静默丢失用户数据。

随机种子、操作序列和失败现场必须可复现。

### 1.3 集成测试

使用临时 NTFS 目录和 FakeEndpoint 验证端到端行为；CI 不依赖真实 NAS。真实 SMB 行为另设集成测试矩阵。

### 1.4 故障注入

在文件复制、Flush、替换、回收、Journal 写入、Snapshot 切换、基线提交等每个边界注入进程终止、IO 异常和磁盘满。测试程序应可在指定 Operation 状态停止进程。

## 2. 必测故障场景

| 编号 | 场景 | 通过标准 |
|---|---|---|
| F01 | 复制 1%、50%、99% 时断网/杀进程 | 正式目标不出现半成品；重启后可恢复 |
| F02 | 新文件替换成功后、Base 写入前杀进程 | 恢复识别目标已提交，幂等推进 Base |
| F03 | Journal 半条记录/CRC 错误 | 只截断无效尾部；中间损坏进入恢复态 |
| F04 | NAS 扫描中断/权限撤销 | 不把未枚举子树视为删除 |
| F05 | SMB 断线后恢复 | 重新探测、补偿对账，无伪删除 |
| F06 | A/B 同时修改同一路径 | KeepBoth，双方内容均可打开 |
| F07 | 一侧删除、另一侧修改 | 修改版保留，不静默删除 |
| F08 | 保持 size/mtime 不变而修改文件中间字节 | 完整指纹审计发现变化 |
| F09 | 目录 mtime/条目数不变但子文件内容变化 | 不因目录快速跳过而漏检 |
| F10 | 两台电脑同时运行同一任务 | 只有有效租约持有者可执行写操作 |
| F11 | 大小写/Unicode/尾随点空格冲突 | 不覆盖、不错误合并，明确提示 |
| F12 | 目标磁盘满/权限变化 | 保留旧版本和恢复记录，Base 不推进 |
| F13 | 事件队列溢出/USN Journal 重建 | 标记 NeedReconcile 并完成补偿扫描 |
| F14 | 10 万/100 万文件扫描 | 内存有界、结果完整性可验证 |
| F15 | 任务数据目录误放在同步 root 内 | 启动校验拒绝运行 |
| F16 | NAS Lease 过期、网络分区、旧客户端恢复 | 不发生双主写入；无法确认时停止写操作 |

## 3. 真实环境矩阵

至少覆盖：
- Windows 10/11 NTFS；
- Windows 文件共享；
- Samba；
- 至少一种主流 NAS SMB2/3 实现；
- UNC 与映射盘；
- 低权限、只读、凭据过期；
- 高延迟、丢包、断线、休眠唤醒。

不能用 FakeEndpoint 结果替代 SMB 实机结论。每种 NAS 记录型号、固件、SMB 版本、挂载/权限方式和能力探测结果。

## 4. 低内存验收

测试 1 万、10 万、100 万文件，包含宽目录和深目录。报告：
- Managed Heap；
- Working Set；
- Private Bytes；
- Native Heap；
- 系统 Nonpaged Pool（单独记录）；
- GC 分配量、暂停时间；
- 队列长度、缓存命中、磁盘索引大小；
- 扫描吞吐与网络读取量。

通过标准不是单次启动时内存低，而是随文件数量增加时进程内存仍受预算控制，且不存在长期增长趋势。产品目标仍为引擎稳态 <40MB、普通同步峰值 <50MB、UI 4–7MB；必须在固定基准机上实测并附原始数据。若未达到，不得更改测量口径宣称通过。

## 5. 数据安全不变量

每次测试后自动核对：
- 源文件内容未被意外修改；
- 正式目标文件内容等于源文件或已确认的冲突版本；
- 被覆盖/删除版本存在于回收区或版本区；
- Base 仅指向已完成并校验的状态；
- 没有把端点错误解释为文件缺失；
- 每个破坏性操作都能通过 OperationId 找到日志和恢复证据。

## 6. 发布门禁

发布前全部满足：
1. 三方判定单测和属性测试通过；
2. 所有故障注入用例通过；
3. NAS → 本地、本地 → NAS 均完成真实 SMB 测试；
4. 双客户端租约测试通过，或明确禁用多客户端模式；
5. 低内存报告通过产品门槛或由产品负责人签署差距接受；
6. 数据目录损坏、磁盘满、断线恢复均有明确诊断；
7. 安全默认值、回收区、删除熔断、KeepBoth 已验证；
8. 用户文档、已知限制和升级风险已更新。

## 7. 开发阶段与退出条件

| 阶段 | 工作 | 退出条件 |
|---|---|---|
| 0 技术验证 | NTFS/SMB 能力探测、租约、崩溃恢复原型、百万文件扫描、内存基线 | 关键风险有实测结论；不满足安全条件的能力明确降级 |
| 1 同步核心 | 三方模型、端点抽象、Journal、计划与执行 | 单测/属性测试通过 |
| 2 事务恢复 | 临时文件、校验、提交状态机、恢复扫描 | 故障注入通过 |
| 3 NAS 双向 | UNC、SMB、断线重连、NAS 内容审计、租约 | 双向真实 SMB 验收通过 |
| 4 监控 | FSW、USN 增量、周期对账、溢出补偿 | 丢事件后最终一致性通过 |
| 5 UI | 任务管理、首次预览、冲突与恢复中心 | UI 不绕过引擎；内存与 IPC 验收通过 |
| 6 稳定性 | 长稳、压力、发布包与升级测试 | 全部门禁通过 |

真实 NAS 验证必须在阶段 0 开始，不能拖到功能全部完成后才发现端点语义不成立。
