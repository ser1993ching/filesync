# FileSync 产品需求文档（PRD）

> 版本：3.0
> 产品定位与硬约束以《产品定义与开发基线》为准；同步算法、事务和端点能力以 v3 技术架构专题为准。
> 当前阶段：产品与技术设计阶段，尚未开始功能编码。

## 1. 产品目标

提供 Windows 上轻量、安全的双目录双向同步工具。用户选择 A、B 两个文件夹，FileSync 自动发现新增、修改、重命名和删除，并将变化同步到另一端。重点支持本地盘 ↔ NAS/SMB 两个方向，NAS 无需安装 Agent。

成功标准：
- 两端最终一致，冲突不静默丢失；
- NAS 暂时不可访问时不误删；
- 进程崩溃后能够恢复或明确暂停，不猜测状态；
- 文件数量增加时内存仍受预算约束；
- 用户能预览、追踪、恢复同步动作。

## 2. 用户与场景

### 场景 A：本地工作目录同步到 NAS
用户在本地编辑文档，FileSync 将变化推送到 NAS。NAS 目标只读、断线或空间不足时，保留本地源文件，明确报告失败。

### 场景 B：NAS 上的文件变化同步回本地
其他设备或用户在 NAS 新增/修改文件，FileSync 通过事件提示和周期对账发现变化，并拉取到本地。若本地也修改了同一文件，进入冲突处理。

### 场景 C：两端同时修改
系统以共同 Base 比较 A/B；两端内容都变化且不相同时默认 KeepBoth，保留两个版本并提供冲突中心。

### 场景 D：NAS 离线
任务进入 RemoteUnavailable，暂停依赖远端缺失的删除判断。恢复后重新探测并对账。

### 场景 E：首次同步
用户先看到只读扫描结果和操作预览，确认策略后才允许执行写入。

## 3. 功能需求

### FR-01 任务管理（P0）
- 创建任务，指定 Task 名称、A/B 路径、同步方向和排除规则。
- 默认 TwoWay；A/B 不预设源端和目标端。
- 支持本地路径、UNC 路径；映射盘需验证当前用户会话中的实际连接。
- 创建前检查路径存在性、可访问性、读写权限、根目录重叠、数据目录是否位于同步范围内。
- 显示任务运行、暂停、等待重连、冲突待处理、恢复中和错误状态。

验收：无权限、路径重叠、端点不可达或数据目录位于同步 root 内时，任务不得进入自动同步。

### FR-02 首次同步预览（P0）
- 对 A/B 执行只读清点。
- 分类展示：两端相同、仅 A 存在、仅 B 存在、内容不同、类型不同、名称不兼容、排除项、扫描失败项。
- 展示新增、覆盖、删除、冲突的数量与容量；支持明细分页和导出报告。
- 支持 KeepBoth、PreferA、PreferB、NewOnly、Skip 等首轮策略；有破坏性风险的策略必须二次确认。
- 用户确认前零写入；确认后重新验证清单指纹，文件发生变化则要求重新扫描。

验收：首次预览阶段不得创建/覆盖/删除正式文件；扫描不完整时禁止给出会触发删除的可执行计划。

### FR-03 双向同步（P0）
- A 新建/修改/重命名/删除，按规则同步到 B。
- B 新建/修改/重命名/删除，按规则同步到 A。
- 支持目录创建、目录改名和目录删除的逐项处理。
- 同步计划与执行分离；执行前复核源和目标现状。
- 不可访问、权限错误、枚举中断或扫描不完整不得作为删除证据。

验收：NAS → 本地与本地 → NAS 的新建、修改、重命名、删除测试均通过；操作方向、日志和结果一致。

### FR-04 冲突处理（P0）
- 以 Base/A/B 三方比较判断单侧变化、双侧变化、删除/修改冲突。
- 默认 KeepBoth，双方内容都可恢复。
- 内容相同但元数据不同可更新 Base，不产生内容冲突。
- 内容是否相同以完整内容指纹为准；时间戳和 quick fingerprint 不能单独定论。
- 冲突中心提供保留 A、保留 B、双方保留、稍后处理和打开位置。

验收：构造两侧同时修改，双方内容均可打开；删除/修改冲突不得静默丢弃修改版。

### FR-05 删除与覆盖保护（P0）
- 删除默认进入任务隔离回收区。
- 覆盖前保留旧版本；无法安全保存旧版本时停止覆盖。
- 删除按数量和比例双阈值熔断。
- 目录删除必须展开为文件级计划。
- 回收区支持查看、定位、还原和按策略清理。
- NAS 离线、权限不足、扫描不完整、租约失效时禁止传播删除。

验收：断开 NAS 或撤销权限期间，另一端文件数量不得因伪删除减少；回收区中的内容可还原。

### FR-06 事务与崩溃恢复（P0）
- 每个文件操作有唯一 OperationId 和持久化状态。
- 先写目标同目录临时文件，完成校验后再提交。
- 不得宣称文件系统与 Journal 天然原子；必须实现恢复协议。
- 启动先恢复未完成 Operation，再启动新同步。
- 不得无条件删除残留临时文件。

验收：在复制、Flush、替换、回收、Journal 提交等边界杀进程，重启后不出现半成品正式文件、不错误推进 Base、不静默丢失旧版本。

### FR-07 监控与对账（P0）
- 本地 NTFS 可使用 FSW + USN 增量加速。
- NAS/SMB 使用事件提示与周期对账；事件不能作为唯一事实来源。
- 队列溢出、USN Journal 重建、断线或监控失效时标记 NeedReconcile。
- 提供最后完整对账时间和扫描完整性。
- NAS 对账采用限速、分级审计，避免过密全量扫描造成网络 IO 压力。

验收：人为丢弃事件后，周期对账能发现变化；目录 mtime/条目数不变但文件内容变化时仍能通过内容审计发现。

### FR-08 NAS 连接与多客户端安全（P0）
- 支持 UNC 与当前用户上下文凭据。
- 凭据通过 Windows Credential Manager 或 DPAPI 保护。
- 断线、认证失败、权限不足有明确状态和重试。
- 同一任务多客户端同时运行必须有可靠 NAS 租约；端点不支持可靠租约时限制为单客户端。

验收：两台机器同时启动同一任务时，不发生双主写入；租约丢失后持有者停止新的破坏性动作。

### FR-09 低内存（P0）
- 流式扫描、磁盘化索引、固定容量缓存和有界队列。
- 固定大小复制缓冲；大文件不整块载入内存。
- 默认传输并发 1，实测后最多配置到 2。
- UI 独立进程、分页/虚拟列表。

目标：引擎稳态 <40MB、普通同步峰值 <50MB、UI 4–7MB。必须报告 Managed Heap、Working Set、Private Bytes、Native Memory，并单独观察 Nonpaged Pool；未实测不得宣称达标。

### FR-10 日志、状态与恢复中心（P0）
- 记录任务、OperationId、方向、相对路径、动作、字节数、持续时间、结果和错误分类。
- 日志不得包含密码、访问令牌或未脱敏凭据。
- 提供按任务、时间、路径、动作和级别筛选。
- 显示未完成操作、恢复状态、回收区和冲突。

### FR-11 轻量 UI（P0）
- 任务列表：路径、双向标识、状态、上次完整对账、待处理、失败和冲突。
- 任务详情：扫描、计划、传输、校验、恢复等阶段。
- 首次同步向导、冲突中心、恢复中心、日志与设置。
- UI 通过 IPC 请求 Host，不得直接改 Base、Journal 或文件。
- 后台持续监控不显示虚假百分比。

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 正确性 | 三方判定覆盖所有存在/修改/删除组合 |
| 数据安全 | KeepBoth、回收区、删除熔断、操作恢复 |
| 可用性 | NAS 断线后可重连并对账 |
| 内存 | 全部队列/缓存/Worker 有界，按固定基准验收 |
| 可维护性 | Core 可脱离 Windows 与 SMB 进行单元测试 |
| 可观测性 | 扫描完整性、最后对账、Operation 恢复状态可见 |
| 兼容性 | Unicode、大小写差异、非法名称、长路径均有测试 |
| 安全性 | 凭据保护、日志脱敏、未知状态禁止破坏性操作 |

## 5. 不在首版范围

- 块级增量传输；
- 云端中继和多设备拓扑；
- NAS 端 Agent；
- 高级内容合并；
- 复杂 ACL/权限映射；
- 未经实测验证的“所有 NAS 秒级实时同步”承诺。

## 6. 验收与发布门禁

所有 P0 功能必须通过《v3-测试策略与可靠性验收》中的单元、属性、故障注入、真实 SMB 和低内存测试。代码完成不等于交付完成。发布前必须附测试环境、结果、失败项、已知限制和风险接受记录。
