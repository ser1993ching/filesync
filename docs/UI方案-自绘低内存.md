# UI 方案｜自绘窗口（零 UI 框架）· 首轮差异确认

> 目标：首次指定两个文件夹时，把"哪些文件不一样"用**窗口**展示给用户选择（全保留 / 以 A 为准 / 以 B 为准 / 只同步新增 / 不同步），且**不引入任何 UI 框架**，UI 自身内存 ≤ 8MB。
> 前置：引擎（33MB 常驻，服务/后台）与 UI 是两个进程，UI 用完即退。

---

## 1. 三层 UI 档位（按内存排序，同一份数据源）

| 档位 | 实现 | UI 额外内存 | 适用 |
|---|---|---|---|
| T0 默认 | CLI 菜单（`init` 交互问答） | **0**（复用引擎进程） | 脚本、服务、远程终端 |
| **T1 `--ui`（本方案）** | **Win32 + GDI 自绘，独立小 exe** | **+4~8MB 工作集**（无托管大对象） | 你要的"窗口看差异再选" |
| T2 `--report` | 生成静态 HTML/CSV，用系统默认浏览器打开 | 本进程 **0**（浏览器内存另算） | 只想看，不想点 |

T1 与 T0 共享同一套引擎与同一份 `firstrun.idx`，行为一致（用 `--ui` 只是换渲染层）。

---

## 2. 为什么独立 exe 而不是进程内开窗

实测：清空大对象后 **Windows 工作集不会自动回落**（引擎进程 27.8→60MB 后仍停在 60MB，只有原生内存释放才降）。
→ 进程内开窗会把 UI 位图/字体/窗口类的内存留在引擎进程里；**独立 `FileSync.Ui.exe` 关闭即整体释放**，引擎不受影响。

```
FileSync.Host.exe (服务, 33MB)  ──named pipe──▶  FileSync.Ui.exe (自绘窗口, 4~8MB)
        │                                             │
   扫描/哈希/判定/执行                       只读：统计 + 分页列表 + 提交决策
```

---

## 3. 数据通路：UI 永不持有清单

| 文件 | 内容 | 谁写 | UI 怎么读 |
|---|---|---|---|
| `firstrun.idx` | 定长记录（40B）：`cls, size, mtimeA, mtimeB, hash16, off, len` | 引擎清点阶段 | **memory-mapped 只读**；按 offset 随机取，不整块加载 |
| `firstrun.paths` | UTF-8 路径池（A 侧/B 侧相对路径） | 引擎 | mmap，按 `off/len` 取当前可见行的路径 |
| pipe 协议 | JSON 单行：`stats` / `page(cls,offset,limit)` / `detail(id)` / `decide(name)` | 引擎应答 | 每次 ≤ 50 行，UI 侧只存当前页 |

- 10 万条差异 → `idx` ≈ 4MB 磁盘，UI **常驻内存只放当前页 50 行**（约 10KB）。
- 滚动 = 重新 `page(offset)`；排序在引擎侧完成（UI 不做排序、不建索引）。
- 决策只上报"选哪一个"，逐条计划与执行全在引擎侧。

## 4. 自绘实现要点（Win32 + GDI，无 WinForms/WPF/第三方库）

| 事项 | 做法 | 内存影响 |
|---|---|---|
| 窗口 | `RegisterClassExW` + `CreateWindowExW`，单顶层窗口 + 一个自绘确认浮层（不用对话框资源） | 空窗口 ≈ 2–3MB |
| 字体 | `CreateFontW` 一个 UI 字体（微软雅黑 9pt）+ 一个等宽字体，**全局复用** | 各 ~50KB |
| GDI 对象 | 启动时创建 3 个 brush + 2 个 pen + 1 个 font，全程复用，**绝不在 WM_PAINT 里创建** | 常数 |
| 双缓冲 | **默认逐行直绘 + `WM_ERASEBKGND` 返回 1 + 局部 `InvalidateRect`**（无大位图）；若闪烁明显，只对"列表窗格"做双缓冲（1200×800×4B ≈ **3.8MB**），不做全窗 | 0 或 ~4MB |
| 虚拟列表 | 只渲染可见行（滚动条自绘，行高固定 22px，虚拟总高 = 行数×22） | 与文件数无关 |
| 绘制调用 | `FillRect` / `DrawTextW` / `TextOutW`（UTF-16 直接输出，不转 ANSI） | 0 分配 |
| 文本处理 | 路径用 `ReadOnlySpan<char>` 分段绘制，超宽则尾部省略号；**不拼字符串** | 每帧 ~0 分配 |
| 交互 | 纯键盘：`↑↓` 移动、`PgUp/PgDn`、`Tab` 切列、`1–5` 选择、`Enter` 确认、`Esc` 退出；鼠标只做点击选中 | 无 hover 动画、无定时器 |
| 重绘 | 只画脏区；状态数字靠引擎事件（pipe 推送）刷新，最多 2 次/秒 | 空闲 CPU ≈ 0 |
| DPI | `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)` + `GetDpiForWindow` 换算 | 0 |
| 资源 | 不打包图标/图片；图标用字符（✓ ▲ ● ▶）或 2 个几何图形 | 0 |

## 5. 界面布局（单窗口，三区 + 底栏，键盘可达）

```
┌ FileSync — 首次同步识别  C:\A ⇄ D:\B ───────────────────────────────┐
│ 统计            │ 差异明细（虚拟滚动，只渲染可见 20 行）             │
│ 相同      9120  │ 类型   路径                              大小      │
│ 仅 A 有   3311  │ ▸不同  docs\报表.docx                  2.3 MB    │
│ 仅 B 有    770  │  仅A   docs\图片\a.png                 1.1 MB    │
│ 两侧不同  2211  │  仅B   docs\合同\b.pdf                 3.4 MB    │
│ 已排除     120  │  ⋮                                                │
│ ─────────────── │                                                   │
│ 明细报告  [R]   │ 选中项：docs\报表.docx                            │
│                 │ A 2025-01-01 10:00  1.2MB   sha=9f2c…            │
│                 │ B 2025-01-01 09:12  1.1MB   sha=1a7e…            │
│                 │ → 该文件属于"两侧不同"，将被按所选策略处理          │
├──────────────────────────────────────────────────────────────────────┤
│ [1] 全保留  [2] 以 A 为准  [3] 以 B 为准  [4] 只同步新增  [5] 不同步  │
│ 选择需再按 Enter 确认（破坏性操作会二次确认）          F1 帮助  Esc 退出│
└──────────────────────────────────────────────────────────────────────┘
```

- 打开只需 1 次 `stats` + 1 次 `page`（50 行）；滚动逐页取。
- 选 `2/3/4` 时弹出**自绘确认条**（不是 MessageBox，避免弹窗样式/内存差异），显示"将移动 3311 个文件到 trash、覆盖 2211 个"，按 `Y` 才提交。
- **提交契约**：`decide` 请求带上启动时的清单指纹；引擎比对当前指纹，不一致则**拒绝**（退出码 8）并要求重新清点，避免按旧数据执行破坏性操作。
- `[R]` 调引擎生成 CSV/MD 报告并用默认编辑器打开（UI 不渲染全量）。

## 6. 内存预算（实测口径）

| 组成 | T1 自绘窗口 |
|---|---|
| Win32 空窗口 + 消息循环 | 2–3 MB |
| 字体/GDI 对象（复用） | ~0.1 MB |
| 列表双缓冲（可选，仅列表窗格 1200×800） | 0–3.8 MB |
| 当前页 50 行 ×（路径+数字） | ~10 KB |
| mmap 的 `idx/paths`（页缓存，可被系统回收） | 0（计入系统缓存） |
| **合计** | **4–7 MB**（对比 WinForms ≥18MB、WPF ≥40MB） |

引擎进程不受影响（仍 33MB），两者**不同生命周期**。

## 7. 施工顺序（约 3 天）

| 步骤 | 内容 | 验收 |
|---|---|---|
| S1（1d） | 窗口骨架 + 三区布局 + `stats` 渲染 + `1–5` 键盘选择 + 退出 | 打开一个真实 pair，数字与 CLI 一致 |
| S2（1d） | 虚拟滚动 + `page()` 分页 + 选中项详情（两侧 mtime/size/hash） | 10 万条差异下滚动流畅，内存不随滚动增长 |
| S3（0.5d） | 确认浮层（破坏性二次确认）+ 提交决策 + 执行进度（读列表逐条刷新） | `prefer-a` 的 trash 数量与提示一致 |
| S4（0.5d） | DPI、高对比度配色、窗口缩放（`WM_SIZE` 重建缓冲）、崩溃兜底（UI 挂了不影响引擎） | 125%/150% 缩放不模糊 |

## 8. 风险与规避

| 风险 | 规避 |
|---|---|
| 自绘 = 没有无障碍（UIA）支持 | 提供 `--ui --screenreader` 时回退到 T0 CLI（读屏友好）；键盘全覆盖已满足基本可达性 |
| 中文输入法/Uniscribe 组合 | 本窗口**无文本输入框**（只有按键选择），天然规避 IME |
| 双缓冲大位图吃内存 | 默认逐行直绘；需要时只缓冲列表窗格，不做全窗 |
| 自绘滚动条细节多 | 行高固定 + 只支持"行滚动"（不做像素级平滑滚动），代码量减半 |
| UI 崩溃影响同步 | 独立进程 + pipe 自动重连；决策只在引擎侧落盘 |
| 30 万条差异时列表卡顿 | 引擎侧预排序 + 只传 50 行/页；UI 不排序不过滤 |

---

## 9. 结论

- 用 **Win32 + GDI 自绘、独立 `FileSync.Ui.exe`、mmap 只读 + 分页 IPC、虚拟列表 + 键盘操作**，可以把"首轮差异确认 UI"做到 **4–7MB**，约等于 WPF 的 1/8。
- 不引入任何 UI 框架/第三方库；代码量约 1000 行，集中在 `ui/` 一个目录，引擎零改动。
- 默认仍是 T0 CLI；`--ui` 是可选增强，"无 UI 也能完整工作"这条原则不变。
