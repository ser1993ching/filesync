# FileSync v3.0：同步引擎与三方状态机

> 状态：实现规范（Normative）
> 版本：3.0
> 本文定义同步决策、扫描完整性、计划生成、执行顺序和基线推进规则。与旧版技术文档冲突时，以本文和《文件操作事务与崩溃恢复》为准。

## 1. 不可违反的正确性原则

1. **事件不是事实**：FSW、USN、SMB Change Notification 只产生 Dirty 提示；决策必须基于重新读取的文件系统状态。
2. **缺失不等于删除**：只有端点可访问、枚举完整、路径范围已确认且本轮扫描成功，才允许将缺失视为删除候选。
3. **基线代表已确认收敛状态**：不得在文件操作尚未完成、结果尚未验证时提前推进 Base。
4. **不确定时停止破坏性动作**：元数据冲突、哈希失败、端点降级、状态损坏、锁失效均转为重扫或人工处理。
5. **可恢复优先于自动继续**：任何未完成操作必须保留可识别的 OperationId 和恢复信息。
6. **内存有界**：扫描、计划、事件、哈希、重试和传输均采用有界批次与背压，不得以全量清单换取简单实现。

## 2. 术语与状态模型

- Task：一个同步任务，包含 A、B 两个端点及唯一 TaskId。
- Base：最近一次已确认同步结果的共同基线，不是 A 或 B 的副本。
- Observation：某端点在一次完整扫描或定点复核中观察到的状态。
- Fingerprint：用于判断内容相同的指纹；元数据与内容摘要分开存储。
- Tombstone：已确认删除的基线记录，用于区分删除与暂时不可见。
- ScanEpoch：一次扫描的唯一编号及完成状态。
- Operation：一个可持久化、可恢复的文件系统动作。

每个路径的状态至少包含：
- 相对路径、节点类型；
- A/B 当前观察到的存在性、大小、时间戳、文件身份（若可用）；
- Base 的存在性、内容摘要及必要元数据；
- 最近成功 OperationId、冲突状态、墓碑状态；
- 端点能力与观察可信度。

不要把“未扫描到”直接写成“不存在”。Observation 必须带有 Complete / Incomplete / Unavailable 等可信度。

## 3. 扫描协议

### 3.1 扫描结果必须带完整性

每个端点扫描产生 ScanResult：
- ScanEpoch、端点身份、根目录身份；
- StartedAt、CompletedAt；
- 是否完整、是否发生访问错误/权限错误/路径跳过；
- 目录级失败列表（有界记录，超限写汇总并标记不完整）；
- 扫描器版本、端点能力快照。

只有 Complete 的扫描才允许生成基于缺失的删除候选。任意子目录枚举失败，应将受影响子树标记为 Unknown；不得把它的所有后代当作已删除。

### 3.2 流式扫描与归并

- 每个目录单独枚举；对两侧同级条目按端点规则排序后进行 merge-walk。
- 不允许同时将整棵目录树加载到 List、Dictionary 或 DataTable。
- 目录项排序键必须保留原始名称，并使用端点声明的比较规则；比较键相同但原始名称不同的项目进入名称冲突处理。
- 目录句柄、枚举器和文件流必须及时释放。
- 对宽目录采用有界排序/外部排序或受限批次，不允许目录宽度导致无界内存增长。
- 扫描取消或进程退出时，ScanEpoch 标记为未完成；不可用于删除判定。

### 3.3 目录跳过条件

目录 mtime、条目数、大小或 quick hash 只能作为提示，不能单独证明子树内容未变化。

允许跳过子树的条件必须同时满足：
1. 有可信的变化序列覆盖该子树（例如本地 NTFS USN Journal ID 未变且读取范围连续）；
2. 起止 checkpoint 连续，没有 Journal 删除/重建、溢出或权限降级；
3. 端点能力与根目录身份未变化；
4. 该端点在本轮没有任何监控丢失或扫描异常标记。

NAS/SMB 第一版不具备可依赖的持久变化日志，因此不得仅凭目录 mtime 和条目数跳过内容审计；可使用元数据减少哈希工作，但必须按审计策略重新遍历。

## 4. 内容指纹策略

指纹分为三层，语义不得混淆：

| 层 | 用途 | 能否证明内容相同 |
|---|---|---|
| Metadata：长度、时间、属性、文件 ID | 快速筛选 | 否 |
| Quick fingerprint：文件头尾/采样区 | 排序与减少完整哈希概率 | 否 |
| Full fingerprint：完整内容 SHA-256 | 内容等价判断与复制后校验 | 是（按工程上可接受的密码学碰撞假设） |

规则：
- 首次建立 Base 时，对参与同步的文件建立完整内容指纹；可分批、限速执行。
- 当本地 NTFS USN 可靠指出文件数据流变化时，将该文件标记为 Dirty 并重新计算完整指纹。
- NAS 端元数据相同不能证明内容未变；按配置的周期审计策略对 NAS 文件重新计算完整指纹。
- 不得用“size + mtime + 头尾 64KB 相同”作为最终不变证明。
- 哈希过程中记录读取前后元数据；若文件身份、长度、时间或可用的 USN 状态变化，丢弃本次摘要并重试/标记不稳定。
- 复制源文件时，在复制前后复核源端；若源在复制过程中变化，目标临时文件不得提交为正式文件。
- 复制目标写入完成后验证长度和完整摘要，再进入提交阶段。

## 5. 三方判定表

对每个相对路径，比较 Base、A、B 的存在性和内容指纹。先排除扫描不完整、端点不可用、名称冲突等情况，再执行以下判定：

| Base | A | B | 决策 |
|---|---|---|---|
| 不存在 | 存在 | 不存在 | A → B 新建 |
| 不存在 | 不存在 | 存在 | B → A 新建 |
| 不存在 | 存在 | 存在且内容相同 | 接纳为共同初始内容，更新 Base |
| 不存在 | 存在 | 存在且内容不同 | 首轮/新增冲突，默认 KeepBoth |
| 存在 | 未变 | 已变 | B → A |
| 存在 | 已变 | 未变 | A → B |
| 存在 | 已变且内容相同 | 已变且内容相同 | 更新 Base，不复制 |
| 存在 | 已变 | 已变且内容不同 | 冲突，默认 KeepBoth |
| 存在 | 删除 | 未变 | 删除 B（先回收），记录墓碑 |
| 存在 | 未变 | 删除 | 删除 A（先回收），记录墓碑 |
| 存在 | 删除 | 已变 | 删除/修改冲突，保留修改版并提示 |
| 存在 | 已变 | 删除 | 修改/删除冲突，保留修改版并提示 |
| 存在 | 删除 | 删除 | 两端均删除，确认墓碑后清理 Base 记录 |

“已变”必须由完整指纹或可证明的文件系统变更证据确认；时间戳差异本身不代表内容变化。若指纹缺失或无法计算，状态为 Unknown，不得猜测。

### 5.1 重命名

重命名不能仅凭“一个路径消失、另一个路径出现”推断。按可信度依次使用：
1. 同一端点稳定文件 ID；
2. 完整内容指纹 + 文件类型/大小等辅助信息；
3. 用户显式选择。

存在多个相同内容候选时，不自动配对。目录重命名按子树操作计划展开，逐文件检查冲突、排除规则和基线变化，不允许整树盲目移动。

### 5.2 PreferNewer

PreferNewer 不作为默认策略。mtime 可能受时区、精度、复制、NAS 实现影响；若用户启用，必须把它定义为显式风险策略：先比较完整内容和可验证时间，时间相同/不可信/精度重叠时转 KeepBoth，并在 UI 中说明可能丢失较旧版本。

## 6. 计划生成与执行隔离

扫描和判定只生成 SyncPlan，不直接修改文件。每个计划项至少包含：
- OperationId、TaskId、ScanEpoch；
- 动作类型、方向、源端/目标端、相对路径；
- 源端预期身份、大小、完整摘要；
- 目标端预期状态（不存在或预期旧版本指纹）；
- 冲突/删除策略、回收位置；
- 前置条件、重试分类、可恢复状态。

执行前必须重新验证计划项的源和目标条件。若文件已变化，标记 StalePlan 并重新扫描，不得按旧计划覆盖。

## 7. 基线提交规则

Base 只在以下条件全部满足后推进：
1. 源端读取完成且源稳定性复核通过；
2. 目标临时文件写入完成；
3. 目标内容校验通过；
4. 目标正式文件提交成功；
5. Operation 的提交记录持久化成功；
6. 基线变更记录持久化成功。

无法判断是否已提交时，进入 RecoveryRequired；先检查 OperationId、目标内容和操作日志，再幂等收敛。不得用“文件落盘成功等于基线已更新”的文字假设替代恢复协议。

## 8. 并发与一致性边界

- 一个 Task 在同一时刻只能有一个有效的状态提交者。
- 同一任务的两个端点可以被其他程序或其他电脑修改；FileSync 不提供分布式强一致锁。
- 第一版要求同一 Task 的多客户端互斥：使用 NAS 任务租约/锁文件（原子创建、OwnerId、LeaseId、心跳、过期时间、持有者复核）；不支持可靠原子创建/重命名的端点应禁止多客户端模式。
- 租约丢失或无法续期时，立即停止新的破坏性操作；正在写入的临时文件保持可恢复状态。
- 路径级锁防止本进程内部同一路径并发执行；状态提交者串行写 journal。

## 9. 可观测状态

至少暴露：
- 最近完整扫描时间、扫描完整性、待审计目录数；
- Dirty 队列长度及是否溢出；
- Base 最后提交时间；
- 端点在线/权限/能力状态；
- 待恢复 Operation 数、冲突数、回收区容量；
- 当前任务租约持有者与有效期（不泄露凭据）。

后台监控显示“持续监控 / 上次完整对账时间 / 待处理数量”，不得伪造百分比进度。
