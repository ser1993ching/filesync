# 监控设计（v3 规范入口）

> 本文原有监控设计包含仅凭目录 mtime/条目数跳过子树等不安全假设，现已由 v3 规范替代。

当前规则：
1. FSW、USN、SMB Change Notification 都只是 Dirty 提示，不是权威变化事实。
2. 本地 NTFS 可用 USN 增量加速，但必须校验 VolumeId、JournalId、NextUsn 连续性；失效后标记 NeedReconcile。
3. NAS/SMB 不假设存在可靠持久变化日志，必须周期对账，并按策略执行内容审计。
4. 端点不可达、权限失败、目录枚举中断、队列溢出均不能形成删除结论。
5. 只有完整扫描才允许产生基于缺失的删除候选；局部失败子树必须标记 Unknown。
6. NAS 对账需要限速、分级和空闲时段审计，避免高频全量扫描造成网络 IO 压力。
7. 对外描述为“实时监控 + 最终一致性保障”，不承诺所有 NAS 固定秒级同步。
