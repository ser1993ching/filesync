# FileSync 产品定义与开发基线 v2.0

> **本文件是当前产品范围、用户体验和开发约束的唯一总纲。**  
> 更新日期：2026-11-23  
> 适用阶段：产品设计收敛、技术实现与验收  
> 技术栈：Windows 10/11 x64、.NET 8、C#、无 SQLite、Win32 + GDI 轻量 UI

## 1. 产品定位

FileSync 是一款面向 Windows 电脑、强调**低资源占用与数据安全**的双目录双向同步工具。用户选择两个文件夹，FileSync 负责持续比较、识别变化、双向传输、处理冲突，并在异常情况下保护数据。

低内存不是附带优化，而是产品核心竞争力之一。目标用户可能使用配置较低、内存有限或同时运行多个办公程序的电脑；FileSync 不应以明显增加常驻资源为代价换取复杂界面或不必要的后台能力。

### 1.1 核心价值

1. **双向同步**：两端任意一侧发生新增、修改、重命名或删除，都能按规则同步到另一侧。
2. **低内存、低干扰**：不加载整棵目录树，不使用重量级 UI 框架，不无限累积事件或任务。
3. **安全可靠**：三方基线判断、冲突保留、删除熔断、回收区、断线保护、崩溃恢复。
4. **易于理解和控制**：首次同步先预览；用户能看到任务状态、进度、冲突、异常与恢复入口。
5. **不要求 NAS 安装程序**：NAS 通过 SMB/UNC 访问，NAS 端不安装 FileSync Agent。

## 2. 支持范围与同步方向

### 2.1 两端对等，不预设源端和目标端

每个同步任务由 A、B 两个目录端点组成。A/B 是逻辑角色，不代表固定的源或目标。默认模式为 TwoWay，两端都可以成为变化来源。

| 场景 | 是否支持 | 说明 |
|---|---|---|
| 本地盘 A ↔ 本地盘 B | 是 | 例如 C:\Work ↔ D:\Backup |
| 本地盘 ↔ NAS 共享目录 | 是 | 支持盘符映射与 UNC 路径 |
| NAS 共享目录 ↔ 本地盘 | 是，必须支持 | NAS 上新增/修改/重命名/删除的内容，应按双向规则同步回本地 |
| NAS 共享目录 A ↔ NAS 共享目录 B | 架构允许，列为后续验收场景 | 由本机作为中继流式传输；不要求 NAS 安装 Agent |
| 外接盘 ↔ 本地盘 | 是 | 设备离线时暂停，不传播推测性删除 |

**特别要求：NAS → 本地盘不是单向下载功能，而是完整双向同步中的一个必测方向。** NAS 侧发生变化时，FileSync 必须能发现变化、判断基线、将新版本拉取到本地，并正确处理本地同时修改的冲突。

### 2.2 NAS 访问与监控原则

- 优先使用 UNC 路径（如 \\NAS\Share\Folder）；映射盘符可接受，但启动时必须解析并验证其实际连接状态。
- 不假设 Windows 服务的 LocalSystem 身份能访问交互用户会话中的映射盘。
- 第一阶段优先采用当前用户上下文运行的后台 Host/计划任务；如未来增加 Windows 服务，必须独立设计 SMB 身份、凭据和会话映射。
- NAS 端不依赖 USN Journal。NAS/SMB 监控采用 FileSystemWatcher（若服务端支持）加定期对账；Watcher 仅作为变化提示，不能作为唯一事实来源。
- NAS 断连、认证失败、共享暂时不可达、休眠唤醒时，任务进入等待/重连状态；不得把“不可访问”解释为“目录已清空”，不得触发删除。
- SMB 凭据通过 Windows 凭据管理器或 DPAPI 保护，不写入配置明文和日志。

## 3. 技术与架构硬约束

| 项目 | 统一决定 |
|---|---|
| 目标平台 | Windows 10 / Windows 11 x64 |
| 运行时 | **.NET 8（按产品要求固定，不升级到 .NET 10）** |
| 发布 | .NET 8 自包含、单文件发布；发布包与运行时版本锁定并记录 |
| 状态存储 | 默认纯托管 journal + snapshot；**不使用 SQLite** |
| UI | 独立轻量进程，Win32 + GDI 自绘；不引入 WPF、WinUI、Electron、WebView 等重量级 UI 框架 |
| 文件监控 | 本地 NTFS：FSW + 可选 USN 增量加速；NAS/SMB：FSW + 周期对账 |
| 同步判定 | 三方比较：上次成功同步基线（Base）+ 当前 A + 当前 B |
| 目录扫描 | 流式枚举、目录级 merge-walk；禁止构建全量文件 List/Dictionary |
| 任务并发 | 默认任务串行调度；传输并发和缓冲区有硬上限 |
| 数据安全 | 首轮只读清点、Dry-run、KeepBoth、删除回收、删除熔断、日志与崩溃恢复 |

## 4. 低内存设计目标与验收

低内存是 P0 级非功能需求，不能在实现阶段被弱化。

### 4.1 设计原则

- 目录扫描按目录流式枚举，使用 merge-walk 比较同级条目，处理完即释放临时对象。
- 不把所有文件路径、指纹、差异项或事件放入内存集合。
- 基线与历史状态以 journal/snapshot 持久化；内存只保留有上限的热点索引/页缓存。
- DirtySet、事件环形队列、重试队列、改名候选索引均设置容量上限；溢出时触发对账，不允许无界增长。
- 文件复制使用固定大小缓冲区和有界并发；大文件不得整体读入内存。
- UI 与同步引擎分进程；UI 使用虚拟列表/分页，一次只加载当前可见数据。
- USN 是本地 NTFS 的可选加速，不为追求 USN 而常驻大量额外对象；不可用时退化到 FSW + 对账。
- 不使用“文件数量无关”作为未经限定的绝对承诺。磁盘状态记录会随文件量增长，但内存必须由有界缓存和分页机制控制。

### 4.2 目标指标

以下是单任务、默认配置、指定测试机型下的工程验收目标；必须同时报告托管堆、进程 Working Set、Private Bytes、峰值和测试条件：

| 指标 | 目标 |
|---|---:|
| 引擎稳态内存 | 目标 < 40 MB |
| 普通同步过程峰值 | 目标 < 50 MB |
| 自绘 UI 独立进程 | 目标 4–7 MB |
| 文件复制缓冲 | 默认 256 KB/传输，严格限制并发 |
| 事件/待办队列 | 固定容量，有溢出降级与补偿扫描 |
| 大目录扫描 | 不因全量文件清单而线性占用内存 |

如特定运行环境下 .NET 8 运行时基线导致指标无法达到，必须先通过实测说明差距、定位分配来源并优化；不得未经用户确认就提高目标或改用重量级框架。性能报告必须注明 Windows 版本、.NET 8 具体补丁版本、文件数量、目录宽度、NAS 类型、并发数和测量工具。

## 5. 同步语义与数据安全

### 5.1 三方基线

每个相对路径记录上次成功同步的基线。判定时同时比较 Base、A、B：
- 只有 A 改变：同步 A → B。
- 只有 B 改变：同步 B → A。
- A、B 都改变且内容相同：更新基线，不产生冲突。
- A、B 都改变且内容不同：进入冲突处理，默认 KeepBoth。
- 一侧删除、另一侧未改变：按删除策略传播删除。
- 一侧删除、另一侧又修改：按冲突处理，不能静默删除修改版。
- 任一端不可访问或扫描不完整：本轮不执行依赖缺失判断的删除。

内容是否相同应以足够强的内容校验确认；不能仅依赖修改时间。mtime 用于快速筛选，不作为唯一冲突依据。

### 5.2 首次同步

首次建立任务时必须先只读扫描两端，输出相同、仅 A 存在、仅 B 存在、两端内容不同、仅元数据不同、排除项等清单和汇总。清点阶段不得移动、覆盖、删除用户文件，不得提前建立会误导后续判定的正式基线。

用户确认策略后，重新校验清单指纹；若文件在预览后发生变化，要求重新清点。支持 KeepBoth、PreferA、PreferB、NewOnly、Skip 等首轮策略；所有可能造成覆盖/下架的策略必须展示具体影响并二次确认。

### 5.3 冲突、删除和恢复

- 默认冲突策略 KeepBoth，双方内容都必须可找回；冲突文件名可读且不覆盖既有冲突副本。
- 删除默认进入按任务隔离的回收区，不直接永久删除。
- 删除阈值按数量和比例双重熔断；超过阈值停止该轮破坏性操作并要求用户确认。
- 覆盖前保留旧版本；至少提供回收区查看、打开位置、还原、永久清理等操作。
- NAS 侧删除必须在 NAS 状态可确认且扫描完整时才传播；网络错误、权限错误、超时、目录枚举失败一律不是删除证据。
- 每项破坏性动作写入可审计日志，包含任务、相对路径、方向、动作、时间、结果和恢复位置。

## 6. 产品功能范围

### 6.1 P0：首个可用版本必须完成

1. 任务创建：选择两个文件夹，支持本地路径、映射盘和 UNC 路径；明确显示 A/B 两端路径和双向模式。
2. 首次同步向导：只读清点、差异汇总、逐项预览、策略选择、风险提示和执行前二次确认。
3. 双向同步内核：新增、修改、删除、重命名、目录改名、同名目录合并；支持 NAS → 本地与本地 → NAS 两个方向。
4. 三方基线与冲突：默认 KeepBoth，冲突可查询、可定位、可解决。
5. 删除安全：回收区、删除熔断、离线保护、目录删除逐项决策。
6. 运行状态：任务状态、上次同步时间、正在处理的文件、已完成/待处理数量、传输速率、失败数、冲突数。
7. 连接管理：NAS 连通性、身份/权限检查、断线重连、凭据保护。
8. 日志与恢复：结构化日志、失败原因、重试、崩溃恢复、回收区还原。
9. 轻量 UI：任务列表、任务详情、首次同步、冲突中心、回收区、日志/设置。UI 采用独立进程与虚拟列表。
10. Dry-run 与安全检查：可在真正执行前查看操作计划；启动时验证路径重叠、权限和端点可访问性。

### 6.2 P1：核心稳定后完成

- 多任务配置和任务模板；任务默认串行，用户可配置有限并发。
- 同步健康报告、长时间未同步提醒、NAS 连接质量与错误统计。
- 版本保留策略、容量上限、批量冲突处理。
- 文件名/路径兼容性检查（Windows 与 NAS 文件系统差异）。
- USN 增量监控优化、改名识别优化、扫描性能优化。
- 自动启动、计划同步、暂停/恢复、限速与空闲时段设置。

### 6.3 P2：明确延后

- 块级增量传输、跨设备拓扑、云端中继、NAS 端 Agent。
- 高级文件内容差异合并、复杂 ACL/权限映射。
- 不应为 P2 功能牺牲 P0 的低内存、数据安全和稳定性。

## 7. UI 与用户操作流程

主界面采用轻量桌面应用，而非仅提供首次同步确认窗口。

- **任务列表**：每个任务显示 A ↔ B 路径、双向标识、运行/暂停/异常状态、最近同步、待处理/失败/冲突数量。
- **任务详情**：当前阶段、文件数与容量进度、速度、预计剩余时间（仅在可估算时显示）、最近操作和端点状态。
- **首次同步向导**：先扫描，再展示新增/覆盖/删除/冲突数量和明细；默认不自动执行有破坏性的策略。
- **冲突中心**：显示相对路径、A/B 文件大小、修改时间、内容指纹状态；提供保留 A、保留 B、双方保留、稍后处理等动作。
- **恢复中心**：查看删除/覆盖回收项，支持预览路径、还原和按保留策略清理。
- **日志与设置**：按任务、路径、时间、动作筛选；配置排除规则、同步方向、删除策略、NAS 连接、资源限制。

进度需要区分首次扫描、计划生成、文件传输、校验、收尾和后台监控。后台持续监控不应显示虚假的“百分比进度”。

## 8. 任务状态机

建议统一状态：
未配置 → 端点检查 → 首次扫描 → 等待用户确认 → 首轮执行 → 实时监控

运行期间可进入：
- Paused：用户主动暂停；
- RemoteUnavailable：NAS/外接盘不可达，等待重连；
- PermissionError：凭据或权限错误，等待用户修复；
- ConflictPending：存在需人工处理的冲突；
- NeedsRescan：Watcher 溢出、USN 失效或状态不可信，需要对账；
- Error：不可恢复错误，保留现场与日志。

恢复后必须先验证端点与状态，再继续同步；不能跳过基线校验直接执行删除。

## 9. 监控、重试与异常策略

- 本地 NTFS：FSW 提供低延迟事件；USN 可选加速，失效后自动退化并补扫。
- NAS/SMB：FSW 事件可能不完整，必须周期对账；默认 SMB 增量对账间隔可配置，长间隔全量校验。
- 所有事件都只是“需要检查”的提示，最终以文件系统实际状态和三方基线为准。
- 有界队列溢出后标记 NeedFullRescan，不能丢弃事件后仍宣称同步完成。
- 文件被占用时退避重试；单文件失败不应无故中断其他文件。
- 断线期间不推进不完整基线，不执行基于远端缺失的删除。
- journal 写入、文件替换和基线提交要有可恢复的事务边界；崩溃后可重放或安全重扫。

## 10. 验收测试矩阵（必须包含方向覆盖）

| 类别 | 测试 | 通过标准 |
|---|---|---|
| 本地双向 | A 新建/修改/重命名 → B | 内容与预期一致，日志方向正确 |
| 本地双向 | B 新建/修改/重命名 → A | 内容与预期一致，日志方向正确 |
| NAS → 本地 | NAS 新建文件、修改文件、重命名、删除 | 本地按双向规则更新；删除受回收区和熔断保护 |
| 本地 → NAS | 本地新建文件、修改文件、重命名、删除 | NAS 按双向规则更新；权限失败有明确提示 |
| NAS 断线 | 同步中断开共享，期间本地继续修改 | 不误删；恢复后对账补齐 |
| NAS 端点 | NAS 只读、凭据过期、权限不足 | 明确报错，不写入、不传播伪删除 |
| 冲突 | A/B 同时修改同一文件 | KeepBoth，双方内容可恢复 |
| 删除冲突 | 一侧删除、另一侧修改 | 不静默丢弃修改版本 |
| 首次同步 | 两端已有不同文件 | 只读预览，未确认前零写入 |
| 崩溃恢复 | 复制中强制结束进程并重启 | 状态可恢复，不漏文件、不错误删除 |
| 大规模扫描 | 大量文件与宽目录 | 不构造全量内存清单，队列有界 |
| 低内存 | 按第 4 节固定测试环境测量 | 达到目标或提交明确的差距与优化报告 |
| 路径兼容 | Unicode、大小写、尾随点空格、保留名、长路径 | 不覆盖、不误判，给出可理解的跳过原因 |

## 11. 开发阶段与交付顺序

1. **阶段 A：同步内核与安全**——端点抽象、流式扫描、三方基线、双向计划、Dry-run、KeepBoth、回收区、journal、崩溃恢复。
2. **阶段 B：NAS 双向能力**——UNC/映射盘、连接身份、NAS → 本地拉取、本地 → NAS 推送、SMB 对账、断线保护；方向测试必须先于自动化发布通过。
3. **阶段 C：持续监控**——FSW、USN 可选加速、稳定化闸门、有界队列、重试和全量补偿扫描。
4. **阶段 D：轻量 UI**——任务列表、首次同步向导、进度、冲突中心、恢复中心、日志与设置。
5. **阶段 E：多任务与性能打磨**——任务隔离、有限并发、内存剖析、压力测试和发布验证。

每阶段均需有自动化测试与可复现的验收记录，不以“代码已写完”代替功能验收。
