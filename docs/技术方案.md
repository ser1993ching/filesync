## 旧方案失效的关键点

- 文件系统提交与 Journal/Base 更新不是天然原子事务。
- 不能用 size、mtime 和 quick hash 作为最终内容相同证明。
- 目录 mtime/条目数不能单独作为跳过子树的依据。
- SMB/NAS 变化通知可能丢失，必须通过对账保证最终一致性。
- 本机 Mutex 不能阻止其他电脑同时运行同一任务。
- SQLite、SQL staging、全量内存清单、单向同步或 LocalSystem 映射盘等旧假设均不属于当前产品基线。

如需查看旧方案的历史背景，请通过 Git 历史查看；新增实现必须引用 v3 规范和测试门禁。
